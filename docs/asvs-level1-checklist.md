# OWASP ASVS Level 1 checklist

SECURITY.md states OWASP ASVS Level 2 as the standard this system is reviewed against. This document walks the full Level 1 baseline instead — the strict subset every Level-2-reviewed system is also expected to satisfy — requirement by requirement, against the repository as it stands today. Chapter V1 (Architecture, Design and Threat Modeling) carries no Level 1 requirements in ASVS 4.0.3 and is omitted for that reason, not because it was skipped.

Each row states the official requirement text, this system's status against it, and the evidence a reader can open. Four statuses are used: **Implemented** (the control exists and is exercised), **Partial** (the control exists but with a stated caveat), **Not applicable** (the requirement assumes a feature — passwords, file upload, XML processing, cookies — this system does not have, by design), and **Limitation** (the requirement applies and the control is missing today). A Limitation row is not a lesser finding than a Gap in another document — it is this document's word for the same thing, chosen to match the term `docs/limitations.md` already uses for an honestly disclosed gap.

**A note on scope.** This checklist was produced by reading the code, configuration and infrastructure scripts each row cites, not by restating what other documents claim. Citations name a file and, where one applies, a symbol; line numbers are not used because they drift. The deployment security baseline of the architecture (ADR-13) is enforced by `infra/Caddyfile` and proven against the live address after every deploy by `infra/scripts/12-hardening-check.sh`, which `.github/workflows/deploy.yml` runs against the application host after the deploy, and again against the same host after the Caddy configuration swap when the dashboard is deployed; the dashboard host is never probed. It checks for a failed TLS 1.1 handshake, Strict-Transport-Security with a long max-age, an enforcing Content-Security-Policy, and no version token on `Server` or `X-Powered-By`. The check skips its cookie clause because no cookie is ever set. It does not probe cipher suites, `Referrer-Policy`, `X-Frame-Options` or `X-Content-Type-Options`, and the rows below say so.
